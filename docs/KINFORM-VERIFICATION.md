- No real AI calls or paid image generation were performed. Matching quality, model access, latency/cost and refusals need a consenting, budgeted pilot.

- `npm audit --omit=dev` reported **11 moderate findings**, all in the dependency chain leading to the `uuid` version used by Expo’s `xcode` tooling; no high or critical findings in that scan. Targeted override attempts did not change the installed graph and were removed. Do not use `npm audit fix --force` to downgrade Expo incompatibly. Review/fix the upstream tooling dependency before native release. Advisory: [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq).
- The locally installed Node 22 runtime emitted an engine warning for agent-browser, which requires Node 24. Browser verification used its packaged native executable; Node 24 is recommended for a clean developer setup.
- Sandboxing blocked the optional React Native DevTools installer (`spawn EPERM`); the app’s browser preview and production web build still completed. Start Expo normally outside CI for watch/reload behaviour.
- Do not rebuild the same Windows API output while its process is running; stop that process first or use a separate configuration/output directory. An earlier locked-file build attempt was rerun successfully after stopping the failed process.
- IIS configuration was **published to a local folder only**. No server installation, public network exposure, DNS, firewall changes, deployment or store submission occurred.

These checks establish a working comparison prototype, not production readiness or scientific matching accuracy.
